# Тест-план PR #1 — Rolea redesign

URL дев-сервера: http://localhost:3000
Demo-режим (без `GEMINI_API_KEY` / Supabase) — это нормально:
- `lib/ai/gemini.ts:140-146` → `generateScene` возвращает demo-сцену
- `lib/ai/gemini.ts:215-216` → `assistStoryField` возвращает фиксированные fallback-тексты
- `lib/ai/gemini.ts:163-173` → `continueStory` возвращает фиксированный narration/character/3 suggestions

## Что изменилось (визуально)

1. Лендинг полностью переписан (hero, How it works, тарифы, FAQ, footer).
2. Тёмная/светлая тема через CSS-токены, без `!important`. Theme toggle в `/app/settings`.
3. Онбординг (`/app/onboarding`) — добавлен 6-й шаг **«Готово»** и кнопка **«AI заполнит мир, героя и роль»** в сайдбаре.
4. Чат истории (`/app/story/vesperia`) — динамические подсказки из ответа API + кнопка **«Перегенерировать»**.
5. App shell — мобильный гамбургер + bottom-nav + командная палитра по `Cmd/Ctrl+K`.

## Тесты

### T1 — Лендинг + переключение темы
**Цель:** доказать, что новые секции отрисовались и токены темы реально переключаются.
1. Открыть `http://localhost:3000`.
2. Убедиться: видны заголовки секций «Как это работает», «Тарифы Rolea», «Частые вопросы» (точная подстрока).
3. Прокрутить вниз — виден футер с навигацией (`Создать историю`, `AI режиссёр`).

**Pass criteria:** все три секции присутствуют. Если бы рефактор сломал страницу — `next build` бы упал, но в рантайме мы увидим 3 явных заголовка.

### T2 — Светлая/тёмная тема через токены
**Цель:** доказать, что `[data-theme="light"]` реально меняет фон через переменную `--bg`, а не оставляет старый тёмный.
1. Открыть `http://localhost:3000/app/settings` (страница `Профиль автора`).
2. Кликнуть кнопку темы (Moon/Sun иконка) — переключится на «Светлая».
3. Проверить через DevTools или визуально: `<html data-theme="light">`. Фон страницы — светлый (RGB ≈ 247 243 255), а не тёмный.
4. Перезагрузить страницу — тема осталась «Светлая».
5. Кликнуть ещё раз — тема стала «Тёмная», `<html data-theme="dark">`.

**Pass criteria:** атрибут `data-theme` меняется + фон визуально меняется на светлый. Сломанный рефактор оставил бы фон тёмным или показал бы flash.

### T3 — Онбординг: review-шаг + AI auto-fill
**Цель:** доказать, что 6-й шаг существует и кнопка «AI заполнит» реально пишет текст в поля (через demo-fallback).
1. Открыть `http://localhost:3000/app/onboarding`.
2. В левом сайдбаре виден список 6 шагов: Жанр, Формат, Мир, Персонаж, Роль, **Готово**.
3. Поля «Мир», «Персонаж», «Роль» исходно пустые.
4. Нажать **«AI заполнит мир, героя и роль»** в сайдбаре. Дождаться завершения индикатора.
5. Открыть шаг **Мир** — textarea содержит непустой текст про «Весперия» или подобное (длина > 80 символов).
6. Открыть шаг **Готово** — там карточки с заполненными значениями (не «Пусто — AI подхватит сам.»).
7. Кликнуть карточку «Мир» — wizard перепрыгивает на шаг 3.

**Pass criteria:** шаг «Готово» существует, кнопка авто-заполняет 3 поля видимым текстом, клик по карточке переключает шаг. Если бы `assistStoryField` падал — показался бы красный баннер ошибки вместо заполнения.

### T4 — Story chat: dynamic suggestions + регенерация
**Цель:** доказать, что подсказки приходят из ответа API (а не статичны) и кнопка regen перезапрашивает ответ.
1. Открыть `http://localhost:3000/app/story/vesperia`.
2. Запомнить (скрин) три исходные подсказки внизу — это статика из `fallbackSuggestions`.
3. В textarea ввести `Назвать свою роль фонарщика` и нажать `Enter`.
4. Дождаться ответа AI (видны narration «Повествование» + character «Лира»). Не должно быть system-сообщения «Подсказки: …» внутри ленты — теперь подсказки рендерятся внизу как кнопки.
5. Подсказки внизу обновились на: `Войти первым`, `Попросить объяснить правила мира`, `Проверить, кто наблюдает из окна` (фиксированный demo-набор из `fallbackReply`).
6. Кнопка **«Перегенерировать»** теперь видна (справа). Нажать её.
7. Последняя пара narration+character заменилась на новую (id-ы новые, но текст тот же — это нормально для demo-fallback). Сообщение пользователя осталось.

**Pass criteria:** новые подсказки ≠ исходным; regen удаляет последний AI-блок и добавляет новый, не дублируя сообщение пользователя. Сломанный код или показал бы исходные подсказки, или вообще не имел бы кнопки regen.

### T5 — Мобильная навигация (гамбургер + bottom-nav)
**Цель:** доказать, что мобильный сайдбар реально открывается, а bottom-nav виден только на мобильной ширине.
1. Через DevTools → Device Toolbar выставить ширину ≈ 390px (iPhone 12).
2. Открыть `http://localhost:3000/app`.
3. Видна верхняя панель с гамбургер-кнопкой; десктопный сайдбар не виден.
4. Внизу — фиксированная панель с 5 иконками + «Ещё».
5. Тапнуть гамбургер → появляется overlay-сайдбар с навигацией (Главная, Истории, Шаблоны и т.д.).
6. Тапнуть пункт «Истории» → URL стал `/app/stories`, overlay закрылся.
7. На мобильной ширине bottom-nav остаётся видимым.

**Pass criteria:** все 4 элемента (гамбургер, overlay-сайдбар, bottom-nav, навигация по тапу) работают. До рефактора мобильная навигация была сломана.

### T6 — Командная палитра Cmd+K
**Цель:** доказать, что палитра открывается по горячей клавише и осуществляет навигацию по результатам.
1. Открыть `http://localhost:3000/app` (десктопная ширина).
2. Нажать `Ctrl+K` — открывается overlay с input «Найти историю, шаблон, мир…».
3. Ввести `Сетт` → в результатах появляется пункт «Настройки» (или «Настройки профиля»).
4. Нажать Enter / кликнуть → URL стал `/app/settings`, overlay закрылся.
5. Снова открыть Cmd+K, ввести `Весп` → есть результат с историей `Тени Весперии`.

**Pass criteria:** палитра открывается, фильтрация работает (по разным сущностям), navigation по выбору работает.
